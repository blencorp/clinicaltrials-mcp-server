The server gives your assistant a small JavaScript SDK in place of dozens of narrow tools. The
assistant writes the exact query it needs, and the server runs that code in a sandbox.

<FlowDiagram />

## Three tools

The assistant uses them in this order.

| Tool | What it does |
| --- | --- |
| `search_api` | Searches the SDK method documentation and a dictionary of response fields. Returns signatures and ready-to-run examples. |
| `describe_schema` | Looks up one entry, such as `ctgov.studies.search`, or lists a namespace, such as `ctgov.stats.`. |
| `execute` | Runs JavaScript in the sandbox, with `ctgov` as a global. |

All three are read-only. [Tools](/reference/tools/) has their inputs and limits.

## Reading every page

A search returns one page of studies and, when more remain, a `nextPageToken`. The SDK has no
helper that follows it. The program passes the same parameters with `pageToken` set to the previous
page's token, and stops when the token is missing. Each page is one call, so the program sets a
page limit. The program above does this, and so does the
[paging recipe](/recipes/#reading-every-page).

## The sandbox

- The program has no network, file system, environment, or subprocess access.
- The only way out is the `ctgov` SDK. Each call goes to the server process, which calls
  ClinicalTrials.gov.
- Each run has a time limit, 15 seconds by default and 60 at most, a memory limit, 64 MB by default
  and 256 at most, and size limits for code, results, and logs.
- The memory limit is the V8 heap. In the separate Deno process, which a server with sign-in
  always uses, the process is also ended when its total memory grows by more than twice the limit plus 96
  MiB, 224 MiB at the default. That covers buffers, which the heap limit does not count.

[Security](/security/) has more.

## ClinicalTrials.gov's limits

ClinicalTrials.gov publishes no rate limit, so the server assumes a modest one and keeps to it for
everyone who uses the server. So the server:

- Starts at most 10 requests each second, with 8 in flight. A call waits its turn for up to 15
  seconds.
- Pauses every call when ClinicalTrials.gov answers `429`, for as long as it asks, and retries
  that call once if the pause is 30 seconds or less.
- Caps the calls in one `execute` run, by default at 100.
- Caches responses for 5 minutes, so a repeated question does not send a new request.

A program can start up to 100 calls at once with `Promise.all`, but they still leave at the rate
above. See [Limits](/keys/#limits) for the rest, and for what the hosted server offers.
