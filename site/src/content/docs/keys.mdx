ClinicalTrials.gov is a public API. It has no API keys, and the server asks for none. What you need
depends on where you run it.

| Where | What you need | Tools |
| --- | --- | --- |
| Your computer: Claude Desktop, Cursor, VS Code, or `npx` | Nothing | All three |
| The hosted `/mcp` | Nothing | Search and schema only |
| The hosted `/mcp/account` | A Google account | All three |

The hosted server is at `https://clinicaltrials.mcp.blencorp.com`.

- On your computer, the server runs the programs your assistant writes, with no sign-in and no
  setting to fill in. [Connect your assistant](/connect/).
- The anonymous hosted URL offers `search_api` and `describe_schema`, and cannot run `execute`. A call to
  `execute` there is answered as an unknown tool.

## Why the hosted server asks you to sign in

On the hosted server, the code your assistant writes runs on a machine that many people share. So
that one person cannot use up the machine or the API for everyone else, `execute` needs a
signed-in account, and the server:

- **Knows who is calling.** Each request carries a token that belongs to your account, and the
  server checks it every time.
- **Applies fair-use quotas to each account.** See [Limits](#limits).
- **Keeps the gate for code.** The documentation tools stay open to everyone. Running code is the
  part that costs a process and upstream requests.

Sign in with Google when your client asks. The client opens a page where you approve the
connection, and then it can use the server until you revoke it.

## What the server stores

In account mode, the server keeps these in its database:

- Your Google identity: the name and email address Google gives it, and the sessions that keep you
  signed in. The Google tokens are encrypted.
- The OAuth clients you approved, and the tokens they use. These tokens are stored hashed.
- Per-account counters for the quotas below.

It stores no API keys, because there are none. The database holds no questions, programs, or
results. The anonymous `/mcp` URL needs no account and stores nothing about you.

## Limits

These are the defaults. A self-hosted server can change them. See [Self-host](/self-host/).

- **ClinicalTrials.gov publishes no rate limit.** The server sends at most 10 requests each second,
  with 8 in flight, for everyone who uses it, and it caches responses for 5 minutes.
- **3,000 SDK calls an hour for each account.** Every call a program makes counts, including ones
  answered from the cache. The count is kept in the database, so it holds across restarts. A call over it fails with `SubjectQuotaExceeded`.
- **10,000 requests a day for each account** to `/mcp/account`.
- **2 programs at a time for each account**, and 8 on the whole server. A call over either limit
  fails with `Busy`: try again in a moment.
- **100 SDK calls in one `execute` run**, cached or not. A call past it fails with `CallBudgetExceeded`.

[Tools](/reference/tools/#limits-of-one-run) lists the limits of one run.

## Where the data goes

Each `execute` run reaches ClinicalTrials.gov only through the server, with the server's own
address. No credential of yours is involved, so there is nothing to keep out of the sandbox.
