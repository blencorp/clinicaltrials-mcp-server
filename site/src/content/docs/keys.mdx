ClinicalTrials.gov is a public API. It has no API keys, and the server asks for none. What you can
do depends on where the server runs.

| Where | What you need | Tools |
| --- | --- | --- |
| Your computer: Claude Desktop, Cursor, VS Code, or `npx` | Nothing | All three |
| The BLEN-hosted `/mcp` | Nothing | Search and schema only |
| A server you host yourself | Nothing, or the sign-in you set up | All three, if you offer them |

The hosted server is at `https://clinicaltrials.mcp.blencorp.com`. It is anonymous: there is no
sign-in, no account, and nothing to configure.

- On your computer, the server runs the programs your assistant writes, with no sign-in and no
  setting to fill in. [Connect your assistant](/connect/).
- The hosted `/mcp` URL offers `search_api` and `describe_schema`, and cannot run `execute`. A call
  to `execute` there is answered as an unknown tool. The two tools search the bundled documentation,
  so the hosted server never calls ClinicalTrials.gov for you.

## Why the hosted server cannot run code

On the hosted server, code your assistant writes would run on a machine that many people share. To
keep one person from using up the machine or the API for everyone else, BLEN's server offers only
the documentation tools. To run queries, use your computer: the server starts there in seconds, with no
account and no per-account quota. The server's own limits for one run, and its pace toward
ClinicalTrials.gov, still apply: see [Limits](#limits) and
[Tools](/reference/tools/#limits-of-one-run).

If you want to offer `execute` to other people, [host it yourself](/self-host/): put it behind your
identity provider (OIDC), or turn on account mode, which adds Google sign-in and per-account
quotas.

## What the hosted server stores

Nothing about you. It has no database, no accounts and no cookies. It uses the address your request
comes from for rate limiting, in memory only. Hosting infrastructure may keep its own network logs.
The [privacy policy](https://github.com/blencorp/clinicaltrials-mcp-server/blob/main/legal/privacy-policy.md)
has the details.

## Limits

These are the defaults. A self-hosted server can change them. See [Self-host](/self-host/).

- **ClinicalTrials.gov publishes no rate limit.** A server that runs code sends at most 10 requests
  each second, with 8 in flight, for everyone who uses it, and caches responses for 5 minutes.
- **100 SDK calls in one `execute` run**, cached or not. A call past it fails with `CallBudgetExceeded`.
- **8 programs at a time on a server, and 2 for each caller.** A call over either limit fails with
  `Busy`: try again in a moment.
- **The hosted `/mcp` limits each address** to a few requests per second, with a short burst. A
  request over it is answered `429`.

A server in account mode adds per-account limits: 3,000 SDK calls an hour (`SubjectQuotaExceeded`)
and 10,000 requests a day.

[Tools](/reference/tools/#limits-of-one-run) lists the limits of one run.

## Where the data goes

Each `execute` run reaches ClinicalTrials.gov only through the server, with the server's own
address. No credential of yours is involved, so there is nothing to keep out of the sandbox.
